# Next.js 16 — App Router rules

## Server and Client Components

- Every component is a **Server Component** unless the file starts with `"use client"`.
- Add `"use client"` only when a component needs state, effects, event handlers or browser APIs — and put it on the **smallest** component that needs it, not on a page or layout.
- Fetch data in Server Components with `await`. Do **not** fetch data in `useEffect`, and do not create an API route just so a page can call it.
- To put server-rendered content inside a Client Component, pass it as `children` (or another prop). A Client Component cannot import a Server Component.
- Props passed from a Server to a Client Component must be serializable: no functions (except Server Actions), no class instances.
- Modules that touch the database or secrets start with `import "server-only";`.
- Only `NEXT_PUBLIC_*` environment variables reach the browser. Everything else is server-only.

## Request APIs are async

`params`, `searchParams`, `cookies()`, `headers()` and `draftMode()` all return
**Promises**. Synchronous access was removed in Next 16.

```tsx
export default async function EventPage({ params }: PageProps<"/events/[slug]">) {
  const { slug } = await params;
  // ...
}
```

- Use the generated global helpers `PageProps<"/route">`, `LayoutProps<"/route">` and `RouteContext<"/route">` instead of hand-writing prop types. They are generated by `next dev`, `next build` and `next typegen`.
- `searchParams` values are `string | string[] | undefined` — handle all three.
- In a Client Component use `useParams()` / `useSearchParams()` from `next/navigation`, or React's `use()` on the promise.

## Routing and files

- Special files: `page.tsx`, `layout.tsx`, `loading.tsx`, `error.tsx` (must be `"use client"`), `not-found.tsx`, `global-error.tsx`, `route.ts`, and `default.tsx` in **every** parallel-route slot.
- `error.tsx` and `global-error.tsx` receive `{ error, retry }`. Call `retry()` to recover — it re-fetches and re-renders (stable since 16.3). `reset()` only re-renders; most tutorials still show it.
- `global-error.tsx` replaces the root layout: it renders its own `<html>` and `<body>` and imports `globals.css` itself.
- Only the root layout renders `<html>` and `<body>`.
- Route groups `(name)` organise files without changing the URL.
- Parallel routes: every `@slot` gets a `default.tsx` (the build fails without it once the layout has another route). A modal slot also gets `[...catchAll]/page.tsx` returning `null`, so navigating away from the open modal closes it. Scope slot layouts with a route group so they don't spill onto sibling routes.
- Intercepting routes count URL segments, not folders: route groups and `@slots` don't count. `(.)events` in `app/(marketing)/@modal/` intercepts `/events/…`.
- Metadata: pages set only their own `title` (the root layout's template adds the brand); `metadataBase` comes from `NEXT_PUBLIC_SITE_URL` (`lib/site-url.ts`). `generateMetadata` uses the same loader as the page.
- `opengraph-image.tsx` / `ImageResponse`: flexbox and inline styles only, and any `<div>` with more than one child needs `display: flex` — `{a} · {b}` is three children; use one template string.
- Internal links use `<Link>` from `next/link`, never `<a href>`. Images use `next/image`; fonts use `next/font`.
- `next/image`: give `width` + `height`, or `fill` inside a positioned parent, plus `sizes`. Use `preload` for the main above-the-fold image — `priority` is deprecated in Next 16. Remote hosts must be listed in `images.remotePatterns`.
- Navigation hooks come from `next/navigation` — never `next/router`.
- Use `redirect()` and `notFound()` from `next/navigation` in server code.
- Request interception lives in **`proxy.ts`** with `export function proxy(request)`. `middleware.ts` is deprecated. The proxy runs on the Node runtime; do not set `runtime: "edge"`.
- Route Handlers: `export async function GET(request: Request, ctx: RouteContext<"/api/events/[slug]">)`, then `const { slug } = await ctx.params`.

## Caching (Next 16)

- Routes are **dynamic by default**. Caching is opt-in with the `"use cache"` directive.
- `cacheLife` and `cacheTag` are imported from `next/cache` — stable, **no `unstable_` prefix**.
- `revalidateTag(tag, "max")` — the second argument is **required**. The one-argument form is a type error.
- `updateTag(tag)` is for **Server Actions only** (the user sees their own write immediately). `refresh()` re-renders the current route.
- Once `cacheComponents: true` is set in `next.config.ts` (class 07), the segment exports `dynamic`, `revalidate`, `fetchCache` and `dynamicParams` are **not allowed**. Wrap request-dependent parts in `<Suspense>` instead.
- Do not use `experimental.ppr` — it became `cacheComponents`.
- With Cache Components on, every page keeps a static part and moves request-time reads (`searchParams`, `cookies()`/the session, uncached queries) into a child component behind `<Suspense>`. Awaiting them at the top of the page makes `next build` fail.
- `new Date()` / `Date.now()` in a Server Component is a prerender error: put it in a `"use cache"` function or read it after `await connection()` (from `next/server`).
- Keep cache tags in `lib/cache-tags.ts` and use them from there — never hand-type a tag string twice.
- A Server Action must expire a tag (`updateTag`) or call `refresh()`, or the page on screen won't update after it — not even an uncached page.
- Never cache per-user or per-request data ("tickets left", the session). Cache shared reads (`getEventBySlug`) with `cacheLife` and `cacheTag`.

## Removed or wrong — never generate

| Don't write                                                  | Write instead                       |
| ------------------------------------------------------------ | ----------------------------------- |
| `pages/`, `getServerSideProps`, `getStaticProps`, `_app.tsx` | App Router files in `app/`          |
| `middleware.ts`, `export function middleware`                | `proxy.ts`, `export function proxy` |
| `const { id } = params`                                      | `const { id } = await params`       |
| `import { useRouter } from "next/router"`                    | `next/navigation`                   |
| `next lint`                                                  | `eslint` (`npm run lint`)           |
| `serverRuntimeConfig`, `publicRuntimeConfig`                 | environment variables               |
| `images.domains`                                             | `images.remotePatterns`             |
| `unstable_cacheLife`, `unstable_cacheTag`                    | `cacheLife`, `cacheTag`             |
